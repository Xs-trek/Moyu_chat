# 前端审查（v0.0.6-beta 阶段 1）

> 状态：第 7 节的改造已在阶段 1 完成（见 CHANGELOG）。V2 已修；V3（系统字体缩放）与 T6（代码高亮）在阶段 2e 完成：正文跟随系统字号（85%–160%），代码高亮为自写的本地轻量实现，没有引入第三方库。

审查对象是 `src/` 与 `index.html` 的当前实现（`claude/beta` @ `32cfc6bc`）。方法：在 `dev/` 预览环境中按 375×812 视口加载各 fixture，浅色和深色各看一遍，并对照源码。截图中的问题都能在 `npm run dev` 里复现。

## 7. 改造方案（与视觉方向无关的部分）

视觉方向只决定颜色、字体、形状和密度，下列结构改动在三个方向中都相同：

1. **流式 Markdown**：按块增量渲染。已闭合的块缓存不重建，只重渲染末尾正在增长的块；未闭合的代码围栏直接显示为代码块；渲染频率跟随 rAF，最高约 10 Hz。流式与完成态使用同一套 DOM，回合结束时不再整体替换。
2. **回复底部**：默认收起为一行摘要（如 `18.4k → 1.3k · 缓存 83% · 23.9s`），右侧放复制和 `⋯`；点击摘要展开完整指标。阶段 2 的调用链会接在这里。流式期间只显示阶段和计时。
3. **消息操作**：回退、分支、编辑收进 `⋯` 底部菜单；回复只常驻“复制”。
4. **标题栏**：`☰`（抽屉）+ 单行标题（副标题为模型名）+ `⋯`（重命名、分支、推理显示、以后的调用链/协议检查）。
5. **侧边抽屉取代底部导航**：顶部“新建”，中间是会话列表（显示模式标记和运行状态），底部是 Provider 和设置入口。`home` 路由保留，作为没有活动会话时的落地页。
6. **输入区**：一行三个控件——`＋`、“本轮设置”芯片（如 `Sonnet 5.5 · 高 · 联网自动`，点开是同时含模型、推理、联网的底部面板）、发送/停止。所有控件 ≥44px。
7. **触控与滚动**：交互控件统一 ≥44px（视觉尺寸可以更小，用热区补足）；恢复时间线的细滚动条；图片根据 `width/height` 设置 `aspect-ratio`；用户气泡内的缩略图限高。
8. **CSS 重写**：采用多行格式和分节；token 分为排版、颜色、形状和动效四组；`static-check` 中逐字的 CSS 断言改成语义断言（例如“存在 `prefers-color-scheme` 分支”“触控 token ≥44px”），安全与边界断言全部保留。
9. **可访问性**：把 `aria-live` 从 `#app` 移到 toast 和流式状态上。

需要改原生、要先确认的两项：V2（窗口主题和系统栏跟随深浅色，约 20 行 Java）和 V3（是否尊重系统字体缩放）。代码高亮（T6）建议推迟：可以引入的本地库（如 highlight.js 的精简包，约 30–40 KB）会增加 CSP 审查面和 APK 体积，收益不大；可以等实际使用中觉得需要时再定。
