# 04 编排模块

## M1 档位的含义 ⚠️（D5）

档位决定“编排帮多少忙”。同一个模型换档位，比较的就是编排的价值，所以每档包含的模块必须确定：

- **极简**：主调用，加上用户打开的能力：联网（模型自己调用的联网工具）、图片、自定义指令。
  - 历史超限时截断最早的回合。
  - 没有压缩、工具结果清除、回查、跨会话检索、路由、校验、子任务、协议续接、提示词模块，**也没有任何隐藏的辅助模型调用**。部署只能走兜底联网时，只用规则规划，不调规划模型。
- **标准**：在极简基础上，加 Claude / GPT agent 应用的上下文机制：
  - 压缩（含工具结果清除）、原文回查、跨会话检索（全局开着时）；
  - 协议续接、可靠性提示词；
  - 子任务按会话设置。
- **智能**：在标准基础上，加路由（每回合）、任务提示词、证据策略、校验修正；子任务默认开。

## M3 辅助开关 ✅（D10）⚠️（“按需联网”开关随 D5 取消）

- 全局设置，接收回合时冻结。只能关掉档位本来会运行的模块。
- **目标开关**：路由、压缩（含工具结果清除）、原文回查、联网规划（只影响兜底联网）、校验修正、子任务。跨会话检索沿用现有全局设置。
- “按需联网”开关随 D5 取消（联网工具就是联网本身，由联网模式控制）。旧设置里的这个值迁移时忽略；统计按新开关组合分组。
- **关闭的统一含义**（D10）：本回合不运行，也不使用它以前的产物；产物保留，重新打开后继续用。
  - 路由按 D8 不再有产物。
  - 压缩关闭时，已有摘要不用。

## M4 模块只在回合开始时决定一次 ✅（`TurnModules`）

- 每个模块开不开，由档位、预设、辅助开关、部署能力、联网模式共同决定。
- 这个决定在接收回合时一次算完，得出每个模块的“开 / 关 + 原因”，记进调用链的接收阶段。后面各阶段只读这个结果。
- 运行中才知道的条件（是否超过阈值、是否有内容没以原文出现），由模块在自己的阶段判断，但“允许运行”这一前提必须来自开始时的决定。
- 原因代码：`mode_off`（档位不运行）、`harness_off`（预设不运行）、`user_off`（用户关闭）、`session_off`（会话设置关闭）、`setting_off`（全局设置关闭）、`no_client_tools`（部署没声明客户端工具调用）、`web_not_auto`（联网模式不是自动）、`no_snapshot`（不是分支）。
- 以前各阶段各自判断，A02 就是这样产生的。

## M5 模块契约

每个模块写清八项。新增模块时先补卡片，再写代码：

> 触发 · 输入 · 产出 · 产物 · 关闭后 · 失败时 · 上限 · 调用链

### 联网 ⚠️（D5）
- **触发**：联网模式为“自动”或“开启”。部署声明了服务商联网就用它，否则用客户端联网工具（web_search / web_fetch）；两者都没有时走兜底（C8）。
- **做法**：
  - 把联网工具交给回答的模型，由模型决定是否搜索、搜几次；系统提示说明什么时候该搜（参照 Claude web search 的“When Claude searches”）。
  - “开启”= 本回合第一轮强制先搜索（对应 ChatGPT 的“搜索”按钮、API 的强制工具选择）。
  - 每回合搜索次数有上限（对应 `max_uses`）。
- **产出**：搜索和抓取结果作为工具结果进入历史（T3）；来源随回答显示。
- **产物**：无。
- **关闭后**：联网模式“关闭”时不提供任何联网工具。
- **失败时**：工具返回错误说明，由模型决定怎么办。
- **调用链**：搜索和抓取次数、来源数、是否强制、是否走了兜底。
- **现状**：先跑规划再预检索，只在规划说不联网时才给工具。

### 路由 ⚠️（D8）
- **触发**：M2，每回合运行。
- **输入**：当前问题和最近一轮。
- **产出**：任务类别和深度，只用于本回合：选任务提示词、决定是否校验。
- **产物**：无，不存进会话。
- **关闭后**：不调用；本回合按“没有路由结果”处理。
- **失败时**：同“关闭后”。
- **上限**：轻量调用，输出 320 token，超时 8 秒。
- **调用链**：类别、深度、置信度、失败原因。
- **现状**：每会话一次，结果存在会话上。

### 工具结果清除
见 C2。
- **产物**：无（只改变发出的内容，库里保留完整结果）。
- **调用链**：清除了几次结果、腾出多少 token。

### 压缩
见 C3。
- **产物**：摘要和它覆盖的范围。
- **上限**：输出 4096 token，后台超时 60 秒。
- **调用链**：记在触发它的回合上：是否发起、是否换入、覆盖了多少条、等待了多久、失败原因。

### 原文回查
见 C4。
- **产物**：无。
- **调用链**：工具阶段记“是否提供”，生成阶段记“回查次数”。

### 跨会话检索
见 C5。
- **产物**：无。
- **调用链**：调用次数、命中会话数。

### 校验修正 ✅
- **机制依据**：Anthropic evaluator-optimizer。适用条件是“有明确评估标准、迭代能带来可衡量价值”；这里的明确标准，是逐条的强制检查规则。
- **触发**：M2，再按预设判断：
  - Reinforced：除写作、创作类外都校验；
  - Balanced：用了外部证据、上下文被截断或压缩、用了子任务、或者这一轮问的是检查类请求时校验；
  - Lean：用了外部证据、上下文被截断或压缩、或用了子任务时校验。
- **输入**：证据账本，包括当前问题、自定义指令、压缩摘要、回答者看到的上下文、各轮工具结果（按工具标注：联网内容、回查原文、子任务结果）、来源列表。任何一项被截断时记为覆盖不完整，并告诉校验器“缺的部分可能是依据，记 unknown 而不是 fail”。
- **产出**：判定和逐条检查；校准后决定采纳、修正或放弃。
- **修正**：最多修正一次，然后复查。只有复查有效、覆盖完整并且通过时，才替换原回答；否则原回答保留它自己的结论，修正版作为“没采用的修正版”保留对照。
- **产物**：无（结论附在回答上）。
- **关闭后**：不校验。
- **失败时**：回答照常；校验记为不可用。
- **上限**：校验 2000 token / 25 秒；修正 ≤8192 token / 40 秒；每回合最多 3 次调用。
- **调用链**：判定、风险、动作、是否修正、是否采用、尝试次数。

### 子任务 ✅
- **机制依据**：Anthropic orchestrator-workers、子智能体。子任务用干净的上下文，只返回精炼结果。
- **触发**：M2；模型调用 delegate_subtask 时运行。
- **输入**：只有父模型写的任务文字。没有对话历史，没有工具，不能再委派。
- **产出**：精炼结果，作为工具结果返回。说明里要求控制在 2000 token 以内（参照 Anthropic：常见 1000–2000 token）。
- **产物**：无。
- **关闭后**：不提供这个工具。
- **失败时**：返回错误说明。
- **上限**：同一模型和推理深度；输出 ≤8192 token，超时 45 秒；每批最多 4 个并行。
- **调用链**：子任务数和用量（单独归类）。

### 提示词模块（可靠性、任务、证据策略）
- 由预设和本回合的路由结果决定。
- 接收阶段记录本回合用了哪些模块。现状只记预设名。

### 会话命名
见 H9、T8。

## M6 单回合辅助开销上限 ⚠️（D12）

- 最坏情况下，一个回合会经历：路由 8 秒、同步压缩最长 60 秒（只在后台压缩没能及时完成时）、4 轮工具调用（含子任务）、校验 25 秒、修正 40 秒、复查 25 秒。
- 每个调用各自有超时，但没有累计上限（现状）。
- **目标（D12）**：
  - 辅助阶段累计 90 秒为上限。计入路由、等待压缩、校验、修正、复查；不计主调用和工具轮。
  - 超过后，跳过还没开始的修正和复查，回答照常定稿；已经开始的调用按自己的超时结束。
  - 调用链记“超出辅助开销上限”和累计耗时。

## M7 模块之间的交互 ✅

- **路由结果**只影响本回合的任务提示词和是否校验。
- **工具结果**（联网、回查、跨会话检索、子任务）进入下一轮、进入历史（T3），也进入校验证据。进入证据时按来源标注类型；被截断时记为覆盖不完整，避免校验器把被截掉的依据判成“没有依据”。
- **压缩摘要**进入校验证据，代表被总结的那段历史。
- **修正版被采用后**，原回答的推理过程和协议续接状态不再对应显示的文字，不展示也不重放。
