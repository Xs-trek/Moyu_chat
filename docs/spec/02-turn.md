# 02 回合、轮次、工具历史、可见性、取消、失败

## 回合（T）

**T1 回合生命周期** ✅（1–5）⚠️（6，D2）

1. **接收**：用户消息、正在生成的回答行和回合记录在一个事务里写入。从这一刻起，消息属于对话记录，之后的失败不会把它退回输入框。
2. **准备**：
   1. 组装上下文；
   2. 换入已完成的后台压缩，必要时等待（C3）；
   3. 路由（每回合，D8）；
   4. 选择工具；
   5. 主机联网检索，只在兜底时（C8）。
3. **生成**：一轮或多轮主调用。模型可以调用工具：联网、原文回查、跨会话检索、子任务。
4. **后处理**：校验，必要时修正和复查。
5. **收尾**：回答定稿（包括本回合的工具调用和结果，T3）；写回合状态和调用链；释放忙碌标记。
6. **回合结束后**：按实际用量判断是否需要压缩，需要时在后台进行（C3）。

每个回合只有一次收尾写入；调用链在收尾最后写，读到“已结束”时回答已经是最终版本。

**T2 回合配置冻结** ✅

- 接收时冻结一份回合配置：部署、模型、推理深度、上下文上限、辅助开关、自定义指令、价格。
- 回合内的所有调用（主调用、辅助调用、子任务）都从这份配置取模型和参数。回合进行中修改设置，只影响下一回合。
- 后台压缩用的是触发它的那个回合的配置。
- T2a（已修）：路由、压缩、校验、修正的模型和推理深度从回合配置取。

**T3 工具调用属于历史** ⚠️（D4）

- 参照 Claude / GPT：工具调用和结果是对话历史的一部分。
  - Claude 的联网结果必须在后续回合原样回传；
  - OpenAI 用 items 承载工具调用。
- 回合收尾时，本回合的工具调用、结果和来源随回答一起保存。后续回合按原样重放；切换部署时，转换成与协议无关的形式。
- 上下文变大时，先按 C2 清除最旧的工具结果。
- 每回合最多 4 轮工具调用，每轮的工具数量有上限；最后一轮不再提供工具。
- 现状：工具调用和结果不进历史，下一回合不重放；用了客户端工具的回合也不保存协议续接状态。

**T4 “模型看到了什么”以那次调用实际发出的内容为准** ✅（`CanonicalPrompt.carries`）

凡是要判断“某段内容模型是否已经看到”，都拿**那一次调用实际发出的提示词**来判断，按**是否包含**判断（检索结果是消息的片段，被某条消息包含就算看到）。

| 环节 | 对照哪次调用 |
|---|---|
| 原文回查排除已有内容 | 发起这次回查的那一轮 ✅ |
| 是否提供原文回查 | 最终组装好的第一轮提示词（加入工具定义和联网证据之后）✅ |
| 校验看到的上下文 | 回答者看到的全部：第一轮上下文 + 各轮工具结果，按类型标注 ✅ |

**T5 取消** ✅（部分）⚠️（D11）

- 用户在任何阶段点“停止”：当前网络调用立即取消；回合以“已停止”收尾，算完成，不算失败。
- 生成中途停止：已经输出的文字保留，标记为未完成，可以重试。
- 排队等路线名额时停止：直接结束。
- 校验或修正阶段停止：回答算完整，校验记为“已取消”（D11）。
- 后台压缩不随回合取消。它属于会话，不属于回合；会话被编辑、回退或删除时作废（C3）。

**T6 失败与降级** ✅

| 类别 | 内容 | 放不下或失败时 |
|---|---|---|
| 必需 | 基础指令（可退到精简版）、当前用户消息、兜底主机联网的证据（只有它一条联网途径时） | 回合失败，原因写进时间线和调用链 |
| 可选 | 工具定义、任何辅助调用的结果、压缩（失败时保留原文，下一回合后再试） | 不带上或跳过，回合照常进行，调用链记原因 |

辅助调用失败或超时，从不导致回合失败，也不留下产物。

**T7 重试** ✅（现状）⚠️（D9）

- 现状：只能重试最后一个本地回合，并且这个回合失败了或没完成。重试会回退到那条用户消息之前，原回合转入归档，用当前设置重发；新回合记 `retryOf` 和第几次尝试。
- D9 实现后：重试 = 在同一条用户消息下产生一个新的回答版本，失败的版本保留。

**T8 回合结束后才回来的结果** ✅

- **会话命名**：按回合 ID 写入；那个回合已归档时写到归档记录，已删除时丢弃；标题只在仍是原值时替换。
- **后台压缩**：只有在被总结的那段历史没有变化（没有编辑、回退、切换版本）时才换入，否则丢弃（参照 Claude 后台压缩：等待期间不能修改已发送的历史，替换时只换掉当时发送的那些消息）。

**T9 并发** ✅

- 同一会话同时只有一个回合；回合进行中，改设置、编辑、回退、删除、重答、分支都会被拒绝，草稿除外。
- 同一会话同时最多一个后台压缩。
- 不同会话可以同时进行，受各自路线的并发上限约束；超过上限的排队，界面显示“排队中”。
