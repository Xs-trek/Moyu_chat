# 机制对照：Claude / GPT 怎么做，Moyu 怎么做

规格的机制以 Claude / GPT 为准（见 [README](README.md#机制来源)）。下表逐项对照，“目标”一列是规格采用的做法；带 D 编号的需要用户确认（[decisions.md](decisions.md)）。

## 一、对照表

| 领域 | Claude / GPT 的做法（来源） | Moyu 现状 | 目标 | 决策 |
|---|---|---|---|---|
| **历史保留** | Agent 应用保留全部原文，接近上限时才压缩（Claude Code、Codex CLI、Claude API 压缩文档：“compact before you outgrow it”） | 标准、智能档每轮按预算滚动截断最旧的回合，另外在 50% 时提前压缩 | 标准、智能档保留原文，接近上限时压缩；截断只作最后手段。极简档保留滚动截断，作为基线 | D1 |
| **压缩时机** | 由应用在**回合结束后**判断，用上一回合实际用量（输入 + 输出）对比接近真实输入预算的阈值（Claude“When to compact”）；可以在**后台**压缩，对话照常进行，摘要到了再替换（Claude“Compaction in the background”）；Codex 有回合前和回合后两种自动压缩 | 下一回合准备阶段同步压缩，用户多等一次调用；触发看本地估算 | 回合结束后按实际用量判断，在后台压缩；下一回合放不下时才等待 | D2 |
| **压缩内容与位置** | 摘要替换被总结的消息，**放在消息最前**（Claude 压缩块；Codex 用摘要前缀告诉模型“本会话接续自之前的对话”）；可以保留最近几轮原文（Claude“keeps recent turns”示例保留 2 轮；Codex 保留最近的用户消息 ≤2 万 token）；再次压缩时，新摘要包含旧摘要和之后的内容；摘要失败时保留全部历史，下一轮后再试；被总结范围内的图片不再发送 | 结构化 JSON 检查点放在系统指令里；覆盖条数之后的原文照常按预算截断 | 自然语言摘要放在消息最前，标明是之前对话的摘要；保留最近 2 轮原文；其余同 Claude | D2 |
| **原生压缩接口** | Anthropic：按需压缩 `compact-2026-09-04`、阈值压缩 `compact_20260112`；OpenAI：`/responses/compact` 和服务端 `compact_threshold`（加密，不可读） | 没有使用 | 先统一用客户端摘要（同一机制，所有部署可用）；部署声明支持后再接入原生接口 | D3 |
| **工具结果** | 工具调用和结果属于对话历史，后续回合要原样回传（Claude 联网搜索结果必须回传 `encrypted_content`；OpenAI 用 items）；上下文变大时先清除最旧的工具结果，保留最近几次（Claude context editing：默认 10 万 token 触发，保留 3 次，用占位文字代替）。Anthropic 称这是“最安全、最轻量的压缩” | 工具调用和结果不进历史，下一回合不重放 | 作为历史保存并重放；超过阈值时，从最旧的开始清除工具结果，保留最近 3 次 | D4 |
| **联网** | 由回答的模型自己决定什么时候搜索，可以多次（Claude web search：“Claude determines when to search”；OpenAI web_search 工具）；用系统提示调节倾向，用 `max_uses` 设硬上限；ChatGPT 的“搜索”按钮强制搜索 | 先跑联网规划（规则 + 模型），再由主机预检索，把证据接在问题后面；只有规划说不联网时才给模型工具（按需联网） | 模型自己决定：服务商联网优先，其次客户端工具。“开启” = 本回合强制先搜索。联网规划 + 主机预检索只在部署两种工具都不支持时兜底 | D5 |
| **检索已省略的历史** | Agent 应用倾向“即时检索”：保留轻量标识，用工具按需读取，而不是预先注入（Anthropic《Effective context engineering》）。MemGPT 论文：只给摘要的基线准确率 32–39%，能用工具回查原文的达到 67–93% | 两套：分支检索（快照片段预注入）+ 原文回查（工具） | 保留原文回查（工具，有论文证据）；删除分支检索（预注入，不是 Claude / GPT 机制，原文保留加回查已经覆盖它） | D6 |
| **跨会话记忆** | Claude：“搜索并引用聊天”通过**工具调用**完成，范围按项目隔离，无痕会话不会被搜到；ChatGPT：保存的记忆 + 引用聊天记录（隐式注入，由系统提炼，不是原文片段） | 每回合预注入其他会话的原文片段（全局开关，默认关） | 采用 Claude 方式：一个跨会话检索工具，模型在用户提到以前的对话时调用。不采用 ChatGPT 方式：它需要一套记忆提炼流程，现有原文片段注入两边都不像 | D7 |
| **路由** | Anthropic routing：对**每个输入**分类，再交给为该类调过的提示或模型；GPT-5：路由器按每个请求选模型和推理深度 | 每个会话分类一次并存下来，之后不再更新；默认关闭 | 每回合分类，结果只用于本回合（选任务提示、决定是否校验），不存进会话；仍默认关闭 | D8 |
| **编辑、重新生成、分支** | ChatGPT / Claude：编辑消息在**同一会话内**产生分支，可以左右切换，旧版本保留；重新生成（含换模型重试）产生兄弟回答；ChatGPT 另有“在新聊天中分支”，复制到该消息为止的历史，原会话不变 | 编辑和回退直接删除后面的消息（转入归档）；换模型重答新建一个分支会话；“分支”新建会话 | 会话内消息树：编辑、重新生成、换模型重答都产生可切换的版本；“分支”保留为“在新会话中分支”。要改数据库 schema | D9 |
| **校验修正** | Anthropic evaluator-optimizer：一个模型生成，另一个按明确标准评估并反馈，循环改进，“在有明确评估标准、迭代能带来可衡量价值时”使用；OpenAI 输出防护只拦截不改写 | 校验 → 最多修正一次 → 复查，只有复查通过才替换，否则保留原回答并附上没采用的修正版 | 保持。是 evaluator-optimizer 循环一次的形式，并满足“未经确认的改写不替换回答” | — |
| **子任务** | Anthropic orchestrator-workers、子智能体：子任务用干净的上下文，只返回精炼结果（常见 1000–2000 token）；Claude Code 的 Task 工具 | 子任务只看父模型写的任务文字，不能再委派，结果作为工具结果返回 | 保持。子任务说明里要求返回精炼结果 | — |
| **推理状态续接** | Claude preserved thinking、OpenAI reasoning items：同一部署内回传 | 同一部署指纹下重放 | 保持 | — |
| **会话命名** | ChatGPT / Claude 自动生成标题 | 首个完成回合后命名一次 | 保持 | — |

## 二、Moyu 自有的机制

这些不来自 Claude / GPT。保留的必须有证明或明确的能力缺口理由。

| 机制 | 结论 | 理由 |
|---|---|---|
| 原文回查（history_recall） | **保留** | MemGPT 论文的对比数据（见上表）；形式上是 Anthropic 推荐的即时检索工具 |
| 联网规划 + 主机预检索 | **降为兜底** | 只在部署不支持任何工具调用时使用，理由是能力缺口，不是机制更优 |
| 分支检索（快照片段预注入） | **删除**（D6） | 没有证明；目标机制已经覆盖 |
| 跨会话原文片段预注入 | **替换**为跨会话检索工具（D7） | 没有证明；Claude 有对应机制 |
| 50% 提前压缩、30% 目标 | **替换**（D1、D2） | Claude / GPT 都是接近上限才压缩 |
| 每会话一次的路由 | **替换**（D8） | Claude / GPT 都是逐个输入路由 |
| 档位（极简 / 标准 / 智能）、辅助开关、调用链和统计 | **保留** | 这是 Moyu 作为实验台的产品要求，不是对话机制：用来比较“编排帮多少忙” |
| “关闭”的统一含义（D10）、对照组隔离（D7 的排除范围） | **保留** | 同上，实验要求 |

## 三、对开发原则的影响

- CLAUDE.md 说“不要以简化为由删减编排”。D6 删除分支检索、D7 替换记忆注入、D5 把联网规划降为兜底，理由都是**换成 Claude / GPT 的机制**，不是为了简化。已由用户确认采用（2026-10-16）。
- “每个辅助模块都能单独关闭、在调用链里看得到投入和产出”继续成立：工具清除、压缩、回查、跨会话检索、路由、校验、子任务都有开关和调用链记录。
- “协议 ≠ 能力”继续成立：模型自己联网、原生压缩、客户端工具，都以模型配置里的显式声明为准。
