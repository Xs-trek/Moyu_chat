## 不成熟的部分

已实现但效果没有验证。审查时不按缺陷处理；改动前要有使用中的观察数据（开发原则 5）。

| 部分 | 现状 | 判断依据 |
|---|---|---|
| 校验修正 | 校验器和回答用同一个部署，有自己检查自己的偏差；风险阈值靠很少的手动反馈校准；“修正版须经复查才替换”刚上线 | 校验反馈（准确 / 误报 / 漏报）的累计；修正版的采用率和用户评价 |
| 路由 | 分类结果对回答的影响没有数据；默认关闭 | 开和关时，校验触发率和回答评价的差别 |
| 压缩摘要 | 摘要丢了多少信息没有度量 | 压缩后的回合里，原文回查的使用频率和命中率 |
| Token 估算 | 选择内容时按字符数粗算；D2 实现后，压缩触发改用实际用量，影响变小 | 调用链里估算值与服务商报告值之比 |
| 本地检索 | 只按字面匹配（英文按词、中文按两字一组），同义改写查不到 | 原文回查和跨会话检索“没有匹配”的比例 |
| 兜底联网的规划规则 | 用正则预判是否可能需要联网，中英文覆盖有限 | 只影响不支持任何工具的部署 |
| 辅助调用的模型 | 默认和主调用同一个部署；可以另选辅助模型（D15），效果还没有对比数据 | 同一类辅助在会话模型和辅助模型上的结果（路由分类、命名）和花费 |
| 统计归因 | 只能比较不同开关组合，相关不等于因果；样本少时趋势不可靠 | 这是“在使用中评测”有意接受的代价 |
| 测试基础 | 端到端测试跑在模拟服务器上；真实服务商的协议差异靠真机和默认跳过的冒烟测试 | 真机清单 `docs/device-checklist.md` |
