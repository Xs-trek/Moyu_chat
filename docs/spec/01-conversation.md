# 01 会话、消息树、分支、历史

## 术语（G）

| 编号 | 术语 | 定义 |
|---|---|---|
| G1 | 会话 Session | 一条对话。有消息、会话级设置（模型、档位、预设、联网模式、推理深度）和模块产物 |
| G2 | 消息树 ✅（D9） | 会话内的消息按父子关系组成树。编辑一条用户消息，会产生这条消息的兄弟版本；重新生成一个回答，会产生这个回答的兄弟版本。实现：时间线每行记父消息（`parent_key`）；错误行挂在它所属回合的回答（没有回答时挂在提问）下面 |
| G3 | 当前路径 | 从根沿“当前选中的版本”走到最新消息的那条路径，也就是界面上看到的对话。参照 ChatGPT / Claude 的版本切换（1/2、2/2）。实现：会话记路径的末端（`leaf_key`），路径从它沿父消息走到根；切换到某个版本时，显示到那个版本下最新的一条 |
| G4 | 新会话分支 | “在新会话中分支”：把当前路径复制到某条消息为止，作为一个新会话的开头（ChatGPT“Branch in new chat”）。现状叫“分支”，用起点快照（`originSnapshotId`）实现 |
| G5 | 快照 | 新会话分支创建时复制下来的那段历史，不可变。快照已经包含源会话自己继承的快照，所以一个快照就是整条祖先链 |
| G6 | 分支家族 | 沿 `parentSessionId` 能连到同一个根会话的所有会话 |
| G7 | 可见消息 | 用户或助手的、已经完成的、有文字或图片的消息，以及助手消息里的工具调用和结果（T3）。错误行、用量行、正在生成的行都不算 |
| G8 | 回合 / 轮次 / 调用 | 回合：一条用户消息到一个最终回答或一个错误。轮次：回合内的一次主模型调用。调用：任意一次模型请求 |
| G9 | 模块 / 产物 | 模块：主调用之外，任何改变模型输入或输出的环节（见 [04-modules.md](04-modules.md)）。产物：模块写入数据库、会影响以后回合的结果，目前只有压缩摘要和标题 |

## 历史（H）

**H1 历史的定义** ✅

会话 S 的历史，是 S 当前路径上的可见消息，按时间顺序：

- 新会话分支：快照 + 本会话自己的消息；
- 会话内消息树（D9）：只算当前路径上的版本，其他版本不算历史。这和 Open WebUI、ChatGPT“从当前叶子沿父链走到根”是同一个定义。

所有回答“S 之前说过什么”的环节都用这个定义：上下文组装、压缩、原文回查、跨会话检索的排除范围。会话命名只看本会话自己的消息，见 H9。

**H2 历史只有一个入口** ✅（`SessionHistory`，见 R2）

编排代码通过同一个组件读取 H1 定义的历史，不直接读时间线和快照。按行操作（编辑、回退、重试、切换版本）和界面显示可以直接读本会话的消息。

**H3 新会话分支复制什么** ✅

- **复制**：当前路径到分支点为止的可见消息。每条保留文字、时间、图片附件，以及工具调用和结果、联网来源（D13）。
- **不复制**：推理过程、协议续接状态（它们绑定部署）、校验结论、用量。
- **压缩摘要**：摘要覆盖的范围完全在分支点之前时，一起复制，分支不必重新压缩（D13）。判断方法：分支历史的开头和摘要覆盖的那段完全一致（覆盖范围的哈希相同）。
- **上限**：2000 条、30 万字。超出时保留最近的完整回合，并标记“已截断”；更早的部分在分支里不存在。
- LibreChat 的分叉实现也是这样：复制路径、去掉私有和运行时字段。

**H4 新会话分支继承的设置** ✅

- 继承：部署参数副本、档位、预设、联网模式、推理深度、子任务模式。
- 不继承：草稿。
- 路由结果按 D8 不再存在会话上，没有继承问题。

**H5 编辑、重新生成、换模型重答** ✅（D9）

参照 ChatGPT / Claude：
- **编辑**用户消息：路径末端移到这条消息之前，原文和图片放回输入框；发送后成为这条消息的新版本（兄弟），在新版本下继续对话。旧版本和它后面的所有内容都保留，可以切换回去。
- **换模型 / 换档位重答**：在同一条用户消息下产生新的回答版本，可以切换。选的模型和档位改成会话的设置（界面顶部看得到），之后的回合也用它。回答对比在这些兄弟版本之间进行。
- **重试**失败的回合，也是产生一个新的回答版本，失败的版本保留。
- **“回到这里”**（回答上）：路径末端移到这条回答，后面的内容保留为另一条路径，不删除任何内容。路径末端后面还有内容时，界面显示“回到最新”。
- **版本切换**：用户消息和回答上显示“‹ 1/2 ›”，切换后显示到那个版本下最新的一条。
- **并排回答**（D16、D17）：输入框里的问题一次发给 2–3 个“模型 × 档位”组合，问题只存一条，几个回答是它的兄弟版本。默认第二路是同一模型的另一档位：主要用来看编排多做的事带来什么；推理深度不作为对比维度，每一路沿用会话的设置（那个模型不支持时用默认值）。全部结束前第一路是路径末端，界面用并排卡片代替这条回答；选中一路后它成为路径末端，会话的模型和档位改成它的，并记为好答案；“差不多”不选任何一路。盲评时卡片只显示“回答 A / B / C”（打乱、按组固定），不显示模型名和用量，选完揭晓。没选就继续对话时，沿第一路继续，这组不计入胜负。
- 这些操作都不新建会话。
- 压缩摘要不随切换删除：它连同覆盖范围的哈希保存，切到别的路径时不用，切回来又能用（C3、T8）。

**H6 新会话分支** ✅

- 对应 ChatGPT“在新聊天中分支”：从某条消息开始，复制到那里为止的路径，原会话不变。
- 用于“换个方向继续，但不想动原会话”。

**H7 对照组隔离** ✅

- 同一个问题的不同回答版本（重新生成、换模型、换档位）是对照组，彼此不能看见。
  - 会话内消息树里，兄弟版本不在当前路径上，本来就不在历史里（H1）。
  - 跨会话检索排除当前会话的所有版本。
- 跨会话检索还要排除同一家族的新会话分支（D7）。否则祖先的内容会重复出现，兄弟分支会互相看见。
- 类似 Claude 的做法：无痕会话不会被聊天搜索搜到。

**H8 删除** ✅

- 删除会话时，同时删除它的消息、检索索引、没人引用的媒体；回合记录转入归档（统计和预算仍计入）。
- 快照在还有分支引用时保留。
- 删除父会话不影响子分支。

**H9 会话命名** ✅

- 首个完成的回合之后，用这个会话的模型命名一次；也可以手动“重新命名（自动）”。
- 命名材料：本会话自己的第一个问题，加上最近一组问答。
- 标题被手动改过就不覆盖。
- 命名调用的开销记到被回答的那个回合上；那个回合已经归档时，记到归档记录上。
