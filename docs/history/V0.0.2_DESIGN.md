# Moyu Chat v0.0.2 — Three context harness modes

## Goal

v0.0.2 intentionally supports three different context philosophies so one Android client can work with models whose reasoning quality, context robustness and protocol capabilities differ substantially.

The product invariant is:

```text
Moyu durable transcript = source of truth
provider-native state    = optional optimization
model preprocessing      = mode-dependent capability
protocol                 = wire shape, not capability
```

Third-party compatible endpoints are the primary deployment case. OpenAI and Anthropic define protocol-family reference shapes, but an endpoint using `openai-responses` or `anthropic-messages` is not assumed to implement the corresponding first-party optional features. Reasoning effort, Messages thinking, hosted Web, image modalities and provider-private continuation are deployment-scoped Model Profile capabilities and default to the conservative/off state unless explicitly declared.

## Modes

### Minimal

Use the model as directly as possible.

- thin stable Moyu authority/safety boundary;
- raw complete conversation turns;
- no Router;
- no cross-chat Memory/RAG caller;
- no Checkpoint model call;
- no verifier;
- no provider-private reasoning replay requirement.

### Standard

Use a mature Chat harness based on the public common design principles of ChatGPT/Claude without pretending their private server implementations are identical.

- stable policy + raw conversation first;
- optional user Memory/RAG when the global switch permits it;
- explicit Snapshot retrieval;
- proactive compaction at 50% effective input use;
- compact toward ~30% effective input use;
- structured Checkpoint + recent lossless turns;
- provider-native same-model reasoning continuation when replayable state is available;
- Web/tool evidence remains non-authoritative;
- no task classifier and no second-pass verifier.

### Smart

Use the strongest Moyu harness when model quality is weak or the task is complex.

Smart = Standard +:

- bounded Task Router;
- reviewed local PromptModules only;
- evidence/completion-honesty rules;
- same-model fresh verifier;
- deterministic verifier schema/evidence validation;
- provisional local risk calibration;
- at most one repair + one re-verification;
- explicit verifier feedback for future calibration.

## Global user memory

A single global setting expresses whether user-level cross-chat memory is allowed at all. It is not itself a context mode.

```text
Memory OFF -> no mode may use cross-chat memory
Memory ON  -> Standard/Smart may use it; Minimal still has no caller capability
```

This keeps the privacy control global while preserving Minimal's definition.

## SQLite state

Current context schema includes:

```text
context_mode
web_mode
task_profile
context_checkpoint
checkpoint_covered_items
thinking_mode
thinking_budget_tokens
continuation_mode
knowledge_fts
settings
```

New derived verifier/provider-native state is stored either beside the assistant timeline row or in dedicated derived tables/settings. It must remain discardable and must not replace visible transcript text.

## Compaction

The default quality-protection envelope is:

```text
trigger = 50% effective input window
target  = 30% effective input window
```

`effective input window` accounts for declared model input cap, reserved output and deterministic safety reserve. The 30% target is best-effort: current user input and mandatory policy are never trimmed to force the percentage.

A Checkpoint covers the oldest history. After a successful checkpoint, covered raw messages are not redundantly replayed in the active provider-neutral prompt. New raw turns accumulate until the uncovered active tail again reaches the trigger.

Snapshot/import capacity truncation and WebView display projection both preserve complete user-led turn boundaries. Large inherited history remains durable and searchable even when the UI sends only a bounded recent inherited tail to the WebView.

## Provider-native reasoning lane

Standard and Smart use a dual-lane design:

```text
portable lane:
  visible user/assistant messages + Checkpoint/Memory/RAG

private lane:
  replayable provider reasoning/thinking state
```

Responses-compatible and Messages-compatible endpoints may use their own native objects, but protocol compatibility alone never enables this lane. The Model Profile must explicitly declare `continuationMode=native`; otherwise provider-private replay stays off even in Standard/Smart. Messages thinking is likewise independent from optional Messages effort support, and reasoning wire mapping defaults to `none` for third-party compatibility.

Private state is eligible only when the Harness mode permits continuation, the deployment capability is explicitly enabled, protocol + provider + model/profile identity still matches, and the history chain has not been invalidated. The private objects are never normalized into fake text reasoning.

Minimal ignores this lane.

## Smart verification

The candidate answer remains the main model's visible answer. The same model may be called again as a verifier in a fresh context.

Verifier schema distinguishes:

```text
status: valid | invalid | unavailable
verdict: pass | fail | partial
features: multidimensional evidence/constraint/honesty checks
findings[]: rule + severity + evidenceIds[] + explanation
```

Moyu first validates the verifier itself. Invalid evidence IDs or incomplete mandatory-rule coverage invalidate the verifier instead of being trusted.

### Cold-start actions

There is initially no user dataset from which to learn trustworthy numerical thresholds. v0.0.2 therefore uses permissive provisional thresholds stored as explicit local constants. Hard deterministic violations bypass the score and request one repair. High-risk valid verifier output requests one repair. Uncertain or invalid verification abstains from claiming a verified answer rather than deleting an otherwise useful response.

The thresholds are intentionally replaceable by later calibration.

### User feedback

Feedback labels verifier quality explicitly (correct catch / false alarm / missed material error / repair outcome). Regeneration, editing, or silence are not correctness labels.

Calibration state is isolated by concrete deployment fingerprint + policy epoch, and only `valid` + coverage-complete PASS/FAIL verification can become feedback labels. Endpoint/credential changes therefore start a fresh calibration epoch. Early data does not immediately rewrite weights; a minimum evidence count is required before a learned calibration head can replace cold-start defaults.

## Web

Web remains a capability plane independent from context mode. Fallback search/fetch content is ephemeral. Hosted provider tools remain deployment-specific: generic `web_search` / `web_fetch` capabilities may use the transport default, while Messages-compatible third-party endpoints may explicitly declare a supported concrete Web tool wire version. Router/Checkpoint/Verifier calls receive only bounded evidence supplied by Moyu and do not silently inherit the main turn's hosted tool loop.

## Safety and authority invariants

- imported system/developer/tool instructions never regain application authority;
- RAG/Web/tool text is data, not instructions;
- provider reasoning state is optimization state, not durable truth;
- Smart verifier cannot modify system policy;
- verification failure never authorizes fabricated completion;
- edits/rollback/branches remain explicit and invalidate incompatible native continuation.
