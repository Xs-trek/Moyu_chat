# Moyu Chat v0.0.2 — Context intelligence without provider lock-in

## Goal

v0.0.2 improves professional task adaptation and long-session continuity without allowing a model to rewrite Moyu's system authority and without replacing the provider-neutral durable transcript with OpenAI/Anthropic private session state.

## New context state

SQLite schema v9 stores the frozen Session context/Web policy plus derived context fields:

```text
context_mode              auto | minimal | smart
tool_capabilities         provider-native Web capability snapshot
web_mode                  off | auto | on
task_profile
context_checkpoint
checkpoint_covered_items
```

The DB column remains named `tool_capabilities` in v0.0.2 to avoid an unnecessary schema v10; its product meaning is only provider-native hosted Web capability (`web_search` / `web_fetch`), not total Moyu networking capability.

`context_mode` is user/application policy and is frozen when a Session is created. The other three fields are derived state; losing them may reduce adaptation/continuity quality but does not destroy the user-visible transcript.

## Session Context Modes

```text
minimal
  Router off
  Checkpoint off
  zero extra preprocessing model calls

auto
  local Chat / local branches: Router off; Checkpoint only on actual truncation
  Remote Snapshot: Router + Checkpoint
  resolution uses only local provenance/state

smart
  Router on
  Checkpoint on when truncation occurs
```

The default mode is configurable for future sessions. Model-card Chat creation and Remote import can explicitly choose a mode. Local edit/rollback/branch operations inherit the source Session mode. Auto never makes a model call merely to decide whether Smart behavior is needed.

## First-turn Task Router

A first-turn Router call is made only when the resolved ContextMode policy enables routing.

On the first user turn of a session/context epoch:

1. Build the normal provider-neutral baseline prompt.
2. Send a bounded recent excerpt to the same selected model with a strict classifier system instruction.
3. Accept only a fixed JSON vocabulary (`domain/taskType/depth/responseMode/contextPolicy/modules/confidence`).
4. Drop unknown labels/modules.
5. Map accepted values to locally reviewed `PromptModules`.
6. Rebuild the main CanonicalPrompt and execute the user request.

The router has an 8-second application-level wait budget and ~320-token output cap. Failure is non-fatal: a neutral TaskProfile is frozen and the main request continues. It is not retried every turn.

This is model-as-controller, not model-authored prompt authority.

## Context Checkpoint

If the main CanonicalPrompt becomes truncated and the TaskProfile uses `checkpoint_recent`, Moyu makes a bounded hidden checkpoint call before the main request.

The checkpoint model can output only:

```text
summary
constraints[]
decisions[]
openQuestions[]
criticalRefs[]
```

Each field is bounded and then serialized by Moyu. It is injected as explicitly non-authoritative historical data. The checkpoint call has a 15-second application-level wait budget and ~1200-token output cap. Failure falls back to recent-tail selection.

No timeline row is replaced by the checkpoint.

## Turn-aware selection

ContextBudgetManager now retains whole user-led turns. It never constructs a CanonicalPrompt whose retained history begins with an orphan assistant turn. Current pending user input remains mandatory.

## Incomplete responses

A finalized assistant row produced by cancellation/provider failure/truncation is marked:

```text
incomplete=true
terminalCode=<reason>
```

Later context contains an explicit partial-response marker. Local Snapshots preserve the flag.

## Unified Web capability

`web_mode` is frozen per Session:

```text
off   no hosted Web and no Moyu fallback
auto  hosted tools remain provider-side auto; Moyu fallback runs only for local freshness/search heuristics or HTTPS URL fetch gaps
on    allows Moyu Search fallback on every text turn; hosted provider tools still remain provider-side auto
```

Provider-native capability is transport-scoped: OpenAI Responses accepts `web_search`; Anthropic Messages accepts `web_search,web_fetch`; Chat Completions never receives a fabricated hosted Web tool. Missing native capability can be filled by bounded Exa Search and local HTTPS Fetch. Fetch is HTTPS-only, rejects local/private/special address ranges, manually revalidates redirect targets, bounds response bytes/content type, and converts supported HTML to text.

Fallback Web material exists only inside the disposable CanonicalPrompt for the current turn and is explicitly marked untrusted reference material, not instructions or authority. Durable assistant state retains only final answer text, sources, and Web backend metadata. Hidden Task Router/Checkpoint preprocessing always uses the no-Web transport overload.

## Provider-native state

OpenAI Responses reasoning items/response IDs and Anthropic thinking/compaction blocks can improve same-provider continuation, but they are intentionally not made authoritative in v0.0.2.

The future architecture is dual-lane:

```text
portable Moyu state (authoritative)
+
optional provider-native optimization state (discardable)
```

Provider-native state must be invalidated by history edit/rollback, provider/model switch, incompatible import, or any event that breaks the native continuation chain.

## Explicit non-goals

v0.0.2 does not add:

- general function/tool loops, MCP runtime, RAG/file search, shell/code execution, or Agent runtime (the bounded Search/Fetch capability above is the deliberate exception);
- arbitrary model-generated system prompts;
- automatic provider/model switching;
- native OpenAI `previous_response_id` authority;
- native Claude compaction authority;
- automatic replay of Remote tool state;
- hidden rewriting/deletion of durable history.
